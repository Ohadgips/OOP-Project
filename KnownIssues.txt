Changes In This Version:

Design patterns introduced:
- Template Method pattern: new abstract class WizardWorkflow defines the fixed skeleton
  of a multi-step input flow (initialize -> processSteps -> completeWorkflow) and leaves
  the variable steps to the subclasses.

- Command pattern: new Command interface (execute / undo). Each accepted step is wrapped
  in a Command and pushed onto a stack, which is what enables 'back'/undo navigation.

- Factory Method pattern: createEntity() is declared abstract in WizardWorkflow and
  overridden by every concrete wizard to produce its own product type.

  Some Examples for factories and their products:
    - LecturerWizard.createEntity()               -> Lecturer / Doctor / Professor
    - CommitteeWizard.createEntity()               -> Committee
    - DepartmentWizard.createEntity()              -> Department
    - CommitteeActionWizard.createEntity()         -> name-pair token (committee, lecturer)
    - LecturerDepartmentActionWizard.createEntity()-> name-pair token (lecturer, department)
    - CompareWizard.createEntity()                 -> name-pair token (entity1, entity2)
    - DuplicateCommitteeWizard.createEntity()      -> name token (committee)
